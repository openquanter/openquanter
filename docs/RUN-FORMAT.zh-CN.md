# run 文件

一次运行产出了什么,以及它是在什么身份下产出的——放在同一个文件里。

```text
openquanter-run 1
body-sha256 7464039f4b07baadc895de05b289c48890bf29a81696dc9644d3fed06e6aa44d
code-commit abc123
data-sha256 f13fcc00812c2632bc6e265a6bc6861ac27cbc38433309a6a5fbb2bb45e48b1c
config-sha256 e67d23e7820c49a8051dac2831f38290f5e72f66c8db5079eeb60d82f14894c0
label L0
pnl 123.456
fills 5
# ts symbol side price qty tag
fill 1700000000000000000 BTCUSDT buy 6000000 5 -
fill 1700000060000000000 BTCUSDT sell 6001000 5 exit
...
```

## 它为什么存在

[`WHY.md`](WHY.zh-CN.md) 的第五堵墙是:没有任何东西能证明过去的结论还成立。
对应的仪器——身份三元组、`baseline invalidated — rebase required` 这个判定——
早就建好了,却**没有地方写下它的答案**,于是一次 parity 结果的寿命等于一个进程,
之后就变成了记忆。

有三件事被"没有文件"卡住,值得说准确,因为路线图此前把**包装**记成了缺口:

- 基准存不下来,所以没有回归护栏
- `oq parity` 无法存在,因为命令行没有东西可以指名
- 归因报告没有可绑定的对象(`FR-ATTRIB-5`)

## 四个决定

**清单在文件内部。** 这就是 D13 的全部要点:一份与身份分离的基准,是一个没有实验
的数字;而"两个必须放在一起的文件",最终一定会被分开。读到 fill 却没有清单的人,
看到的是一个无法比较的东西,解析器会**拒绝**它,而不是去比较它。

**文本、按行。** 基准写一次,可能几年后才被读——读它的人也许正在主张"这个结果从来
就不可复现"——所以它必须能在没有本程序的情况下被读懂。`grep`、`diff`、对 fill 段
直接 `pandas.read_csv` 都能用;列名写在文件里,而不是写在一份需要人去找的文档里。
二进制会更小,代价是让这份档案依赖一个必须仍然存在、且仍然一致的解码器。

**正文被哈希。** 不是为了防篡改——能改文件的人也能改哈希——而是因为"磁盘满导致
截断"才是现实中会发生的失败,而一份"就存活下来的那部分而言是匹配的"基准,比没有
基准更糟。哈希放在头部而不是尾部,这样读的人可以边流式读边校验。

**本构建不认识的版本会被拒绝。** 不迁移,也不部分读取。"认识什么就读什么、其余
忽略",正是一份新引擎写的基准被旧引擎比对、然后把格式差异报成回归的方式。

## 这个格式坚持区分的东西

| | |
|---|---|
| 一次没有成交的运行 | 写 `fills 0` |
| 一个没写完的文件 | 没有 `fills` 行,以"截断"被拒绝 |
| 没有 tag 的成交 | 写 `-` |
| tag 是空字符串的成交 | 照写,且它不是 `-` |

"计数与行数不符"与"哈希不符"是分开抓的,因为它们是不同的缺陷:前者是写入方的 bug,
后者是传输的问题,而前者的文件在内部是自洽的。

## 怎么读

```text
oq parity baseline.run candidate.run
```

退出码:`0` 一致,`1` 有差异,`2` 参数不对,`3` 基准已失效或读不出来。**是三种结果
而不是两种**,理由和 `oq-recon` 有三种一样:"我没能检查"不等于"我检查过并且没问题"。
一个把"基准已失效"当作通过的 CI,是一个回归护栏已经悄悄停止守护的 CI。

## 刻意不做的

不压缩:一次运行输出是几十 KB 到几 MB,任何常规工具都能压得很好。没有 schema 演进
机制:版本行是一次**拒绝**,不是一条迁移路径。暂时没有资金曲线——`FR-RESEARCH-4`
要求它,而这个格式目前只承载成交和已实现盈亏;加上它就是一次版本号上升,而版本行的
存在正是为了让那次上升在旧读取器上变成拒绝,而不是一次无声的误读。
