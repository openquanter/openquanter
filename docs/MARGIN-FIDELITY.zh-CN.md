# 保证金保真度：没有保证金模型的回测，错得有多离谱？

不建模强平的回测，不是漏了一个细节，而是在回答另一个问题——*如果交易所永远
不能关闭这个账户，这个策略能赚多少*——然后把答案当成第一个问题的答案交出来。
本文定义度量这个差距的工具，说明它能主张什么、不能主张什么，并给出它在一个
"差距很大"的策略上跑出的真实数字。

这是路线图中 **G5** 门的方法学依据，见 [ROADMAP](ROADMAP.zh-CN.md)。

## 对照臂

`MarginMode::Ignored` 不是调试开关。它**正是**一个没有保证金模型的回测在暗中
所做的假设。因此用 `Enforced` 和 `Ignored` 跑同一个策略、同一批 tick，度量的
是一件确切的事：那个假设造成的误差。其余全部相同——同一个策略对象、同一批
tick、同样的手续费、同样的资金费。比较两个模型是弱得多的实验；这里比较的是一
个模型与它自身的缺席。

## 为什么不用均值

最直觉的汇总是收益率之差的平均。它是错的统计量，原因是结构性的而非统计性的。

两条臂在第一次强平之前**逐 tick 完全相同**。在那之前，overlay 什么都不改变；
在那之后，一条臂空仓，另一条臂持有一个任何交易所都不会允许的仓位。所以差异
在绝大部分位置是零，在少数几个位置极大。任何在整条序列上取平均的统计
量——平均收益、夏普、乃至最大回撤——都会把这种集中度除以运行长度，然后为一个
致命差异报出一个很小的数。

## 为什么也不用单次运行内的收益序列

下一个自然想法是在一次运行内部取**收益序列**的分位数。`tail_divergence` 正是
这么做的，而结果是一个有用的**否定结论**：

```
tail divergence   paired over 460 return samples
                  arms part at sample 459 of 460

  quantile        enforced      margin-free     overstated by
        1%        -14.6406%       -17.9768%         -3.3362%
        5%         -4.3673%        -4.5896%         -0.2223%
       10%         -1.2137%        -1.2300%         -0.0162%
       25%         -0.0488%        -0.0488%         -0.0000%
```

两条臂在第 459 个样本（共 460 个）才分开——也就是恰好在强平处，此前从未分开。
配对分位数**按构造**几乎相同，它们显示的小数字**不是**"保证金无所谓"的证据。
就在这同一次运行里，账户最终权益是 61.53，而 margin-free 臂声称 20,908.11。
损害完全在配对区间之外。这就是为什么要报告 `Fidelity::paired_until`，以及为什
么所有配对统计都在那里停止，而不是继续去差分两条已经不再描述同一个账户的序列。

这一点值得明说，因为这个工具是现成的、且容易被误读：**不要把单次运行内的尾部
分位数当作保真度结论来引用。**

## 观测单位是"窗口"

正确的观测是每个**窗口**一个数：每条臂在一段行情上的总收益。窗口与自身配对，
不存在截断，而跨窗口的分布有一个有意义的尾部——多数窗口平静、两条臂一致；少数
窗口含有账户没能挺过去的回撤，在那里两条臂完全不一致。

在四十个合成行情窗口上运行（28 个平静，12 个含 22%–68% 的崩盘），策略是
martingale 加仓阶梯——选它是因为它是最清晰的案例，而不是因为它有代表性：

```
  per-window return, by quantile
    quantile      enforced    margin-free       gap
          5%       -97.71%          -2.84%     94.87%
         10%       -96.77%          -2.06%     94.71%
         25%       -94.91%          -1.28%     93.63%
         50%        -1.32%           0.43%      1.75%
         75%         0.41%          99.58%     99.18%
```

把 5% 行和 50% 行放在一起读。在中位数上两条臂相差不到 1.75 个百分点：overlay
没有咬合，margin-free 回测是对的。在第 5 百分位上，账户亏了 97.71%，而
margin-free 回测报告的是亏 2.84%。

然后**横着**读 5% 那一行，而不是竖着读。margin-free 臂**最差**的窗口不过是些
普通的小亏损。那些毁掉真实账户的窗口根本不在它的左尾——它们在它的**右尾**，
在 +99.58% 以上，因为一个穿过深坑又爬出来的仓位会把反弹记为盈利。**margin-free
回测不只是低估了这些窗口，它把它们归入了成功。**

## 哪些数随窗口配比变化，哪些不变

一项研究里"受压窗口"的比例是一个选择。三个统计量中两个随它变化、一个不变；
不加区分地引用，等于在引用自己编造的数字：

| 统计量 | 随配比变化？ |
|---|---|
| 平均差距 | 会——大致与受压窗口比例成正比 |
| 最差十分位占比 | 会——全是崩盘的研究会报出约 10% |
| **强平条件下的收益** | **不会**——以"发生了强平"为条件 |

条件统计量是唯一可以单独引用的：

```
  in the 12 windows that closed the account:
    the account got               -96.23%
    the margin-free run said      599.89%
```

这句话在往研究里补进任意多个平静窗口后依然成立，而
`StressReport::given_liquidation` 正是按这一点被测试的：补进九十个平静窗口会
让平均值坍缩五倍以上，而条件数对不变。

随配比变化的数字仍值得报告，但必须与配比一起：

```
  windows         40 (28 calm, 12 stressed by construction)
  mean gap        208.83%   <- 一个朴素比较会报出的数
  worst decile      61.0%   <- 它承担的总差距占比
```

## 本文没有确立什么

- **不是频率主张。** 28:12 的配比是为了让尾部有观测值而选的，不是对市场崩盘
  频率的估计。这里任何数字都不应被读作破产概率。
- **不是策略主张。** martingale 阶梯是最清晰的演示，不是典型策略。一个会止损
  的策略差距会小得多——而在这样的策略上做研究却发现没有差距，本身就是一个真
  实结论：对它、在这批数据上，margin-free 回测是够用的。这种情况下
  `worst_decile_share` 与 `given_liquidation` 都是 `None` 而不是零，因为"问题
  没有出现"和"答案是零"是两个不同的发现。
- **未按真实交易所标定。** 阶梯表用的是 `TierTable::example_btcusdt()`。真实的
  维持保证金表因交易所、因合约、因时间而异；要用于真实部署的研究必须用真实的表。
- **合成行情。** 窗口来自生成器而非历史。换成实采数据只改变 `Window::of` 的输
  入；工具本身不假设数据是合成的。

## 复现

```text
cargo run --release --example martingale_ladder   # 单个窗口，细看
cargo run --release --example margin_fidelity     # 四十窗口研究
```

工具在 `oq_backtest::fidelity`：`tail_divergence` 做运行内比较并划出其边界，
`Window::of` 与 `stress` 做跨窗口研究。两者都**拒绝**而不是**取整**：数据支撑
不了的分位数返回 `Unusable::TooFewSamples`，而不是悄悄报出最小值；tick 数不同
的两次运行会被判定为"不是同一个实验"而拒绝。
