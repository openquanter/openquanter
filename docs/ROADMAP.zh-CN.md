# OpenQuanter — 路线图

> 状态：**评审稿** · [English](ROADMAP.md)
> 配套文档：[需求规格说明](REQUIREMENTS.zh-CN.md) · [实施方案](IMPLEMENTATION.zh-CN.md)

本路线图描述从当前 pre-alpha 骨架到 1.0 的路径，以及此后的研究方向。它按
**里程碑**组织，而不是按日期。里程碑有**启动触发条件**与**验收门**：工作不因为
日历到了就开始，也不因为有人觉得差不多了就结束。

人周估算是小团队的指示性规划区间，已包含冗余系数。它们是估算，不是承诺。

---

## 指导原则

1. **先立锚点。** 确定性与 parity 工具优先于功能。没有它们，之后每一次改动都是
   在猜。
2. **保真度先于 AI。** 在低保真仿真器上做强化学习，等于教模型利用仿真器缺陷。
   AI 里程碑以保真度里程碑为前置。
3. **风险价值与性能价值同等重要。** 保证金建模的优先级高于提速工作，因为一个
   不会爆仓的回测，恰恰在最要命的地方是错的。
4. **昂贵的部分用触发制，不用排期制。** 实盘、高频保真、AI 扩展各自带明确的
   启动条件；条件不满足，里程碑就不启动。
5. **数据有时效，代码没有。** 没采到的那一天行情永久缺失。因此采集基建从 M0
   就开始，早于消费它的代码存在。

## 里程碑总览

| 里程碑 | 主题 | 累计人周 | 状态 |
|---|---|---|---|
| **M0** | 地基：仓库、采集、统计 | 3–6 pw | 基本落地 |
| **M1** | 确定性内核、L0 引擎、保证金骨架 → 首个预览版 | 15–27 pw | 大部分已落地 |
| **M2** | Python tier、保证金保真报告、研究工作流 → beta | 24–41 pw | 已承诺 |
| **M3** | 实盘：网关、风控闸门、对账 | 39–62 pw | 触发制 |
| **M4** | 高频保真：L1 排队/延迟、L2 订单簿重建 | 54–83 pw | 触发制 |
| **M5** | AI 扩展：推理、RL 环境、特征层 | 62–97 pw | 触发制 |
| **1.0** | API 稳定化与语义化版本 | — | M3 完成且有外部采用之后 |

M0 与 M1 标"落地"指**范围内多数已建成并有测试**，不等于验收门已通过。截至最近
一次修订：确定性内核、L0 撮合、保证金叠加层、回测宿主、parity 工具、采集工具、
过拟合统计均已就位且全绿。M1 验收门上仍未达成的是：CI 中的 criterion 基准，
以及对参考实现的逐笔 parity——接近但**尚未通过，而差一点的门就是没过**。
常驻采集目前仍是试采而非服务。已建/未建的划分见 README。

"已承诺"指当前默认计划。"触发制"指该里程碑有下文写明的启动条件，条件满足前
不会开工。

## M0 — 地基

**目标。** 把那些"晚做就贬值"的事情先做掉，并搭好接受外部贡献的最小脚手架。

**范围。**

- 公开仓库脚手架：workspace 布局、Apache-2.0、DCO 强制、CI（构建、测试、fmt、
  clippy 全告警即失败）、`AGENTS.md` 约定。
- crates.io 名称占位（`oq-*`），防止命名空间被抢注。
- **行情采集工具与常驻采集。** 完整增量深度、最优买卖价、聚合成交、标记价与
  资金费率、强平订单流，以及每日快照的杠杆/维持保证金分级表。每条记录双时戳；
  原始消息原样归档；重连打 gap 标记；时钟偏移估计随数据归档。
- **过拟合统计**（DSR、PBO/CSCV）实现并可独立使用，让研究质量在新引擎到位之前
  就先改善。
- **仿真场景目录**：把系统必须扛住的通用失败模式写成文档——乱序或重复的成交
  回报、撤单丢失、合成的零价成交、用户流僵死、重连风暴、行情 gap。它们是
  `oq-sim` 的种子语料。

**验收门。**

- 采集持续运行，有实测 gap 率与文档化的存储增长。
- DSR/PBO 可在真实扫描输出上计算。
- 场景目录 ≥ 6 条，每条带可复现描述。
- 公开 CI 在 workspace 骨架上全绿。

## M1 — 确定性内核、L0 引擎、保证金骨架

**启动条件。** M0 验收门通过。这是锚点里程碑：后续一切都依赖这里确立的不变量。

**范围。**

- **先做 `oq-parity`** —— 逐笔 diff 与差异归因；基线由 (commit, 数据哈希,
  配置哈希) 三元组标识，基线过期时自报过期，而不是伪装成一次回归。先造量具、
  再造被测物，是刻意安排。
- `oq-types`：领域类型、`i64` 定点运算、typestate 订单与持仓状态机。
- `oq-journal`：mmap 追加日志、快照、重放、撕裂尾容错。
- `oq-core`：sequencer、确定性内核、注入时钟、标的分片。
- `oq-engine` L0：tick 回放撮合，规格精确到其语义可被冻结为回归锚点。
- `oq-margin` 骨架：分级维持保证金表（双时间存储）、逐 tick 保证金占用、
  强平价计算。
- `oq-backtest`：跑批调度、资金费结算、记账、结果导出、参与率测量、保真度报告。
- 引擎与保证金的属性测试；`oq-sim` 雏形跑通 M0 目录的头几条场景；
  `criterion` 基准进 CI。

**验收门。**

- **G1** —— journal 重放输出完全一致。
- **G2** —— parity 工具证明与参考实现逐笔一致，P&L 相对误差 ≤ 1e-6。
- 属性测试套件全绿，含保证金不变量。
- **首个公开预览版（0.x tag）**，附样例数据与一个示例策略。

## M2 — Python tier、保证金保真、研究工作流

**启动条件。** M1 验收门通过。

**范围。**

- `oq-py`：兼容模式正式化；达速模式设计并实现（订阅粒度、批量回调、状态镜像）。
- **保证金保真报告（G5）。** 在开/关保证金两种模式下复算历史极端行情窗口，并
  公开**尾部偏差报告**的方法论。对杠杆策略而言，这是整个计划中价值最高的单一
  交付物：它量化了无保证金回测究竟乐观了多少。
- `oq-data`：双时戳 Arrow/Parquet 层、双时间参考数据、严格 as-of join 工具；
  `oq-features` 骨架。
- `oq-cli`：`backtest`、`sweep`、`replay`、`parity`、`data` 子命令；集成
  `oq-stats` 使扫描默认输出 DSR/PBO。
- **采用就绪度（G11）：** 快速上手文档、至少两个示例策略、带 golden 测试的样例
  数据集，以及一次由核心团队之外的人完成的冷启动验证。

**验收门。**

- **G3** 吞吐与 **G4** 扫描目标达成。
- **G5** 保证金保真验证通过；尾部偏差方法论公开。
- **G7** —— 策略在兼容模式下零改动运行；改造为达速模式后重新通过 parity。
- **G11** 初验：外部冷启动 ≤ 30 分钟。
- **Beta 发布**，API 已文档化但仍不稳定。

## M3 — 实盘交易

**启动触发条件（全部满足）：**

1. 公开内核已发布 ≥ 6 个月且无未决 P0/P1 缺陷。
2. 有策略以影子模式对着真实交易所跑了足够长的时间可供比对，且影子运行与交易所
   之间的每一处分歧都被**归因**，而不是被容忍。
3. 带仓切换流程已在测试网成功演练至少两次。
4. 至少有一个真实的第三方用户在使用本框架——对小团队而言，外部使用是唯一诚实
   的质量信号。

**范围。** 人周刻意向连接与对账倾斜，而非内核：在这类系统中，事故绝大多数发生
在交易所边界与状态对账层，而不是撮合内核。

- `oq-gateway`：参考永续适配器——行情、下单、用户流——并把**对账作为一等设计
  对象**：回报丢失、重复、乱序的完整处理路径。外加连接器一致性测试套件。
- 按同一契约实现更多交易所适配器。
- `oq-risk`：RiskGate，含盘前检查、kill switch、启动对账与"未知状态即致命"语义。
- `oq-live`：进程装配、快照恢复、平滑重启、每账户一进程。
- 可观测性：在定义好的测量边界埋延迟直方图、结构化指标、告警接入钩子。
- `oq-sim` 全量：整个场景目录 + 网关 fuzz（断连、乱序、重复、部分成交）。
- **带仓切换 playbook**，端到端演练通过。

**验收门。**

- **G6** 延迟目标在定义边界上达成。
- 影子运行一致率达标，每一处分歧都有归因。
- 全场景目录在 fuzz 下通过。
- 灰度上线稳定运行 ≥ 2 周。

## M4 — 高频保真

**启动触发条件（两条都满足）：**

1. 存在具体的（而非假设的）做市或高频策略候选，且其 edge 受仿真保真度限制。
2. 已积累至少 6 个月的增量深度数据。

**范围。**

- **L1**：排队位置建模（先上保守档；概率档只有在用真实成交记录校准后才启用）、
  用分布而非常数表示的三段延迟、平方根冲击罚项、参与率告警。
- **L2**：由增量深度重建订单簿并在其上撮合，配快照对账与 gap 处理。
- 风格化事实测试集进 CI（厚尾、波动率聚集、订单流自相关），验证仿真器行为像
  一个真实市场。
- 同一策略在 L0 / L0+margin / L1 三档的对比报告。

**验收门。** **G8** 达成，外加一份对比模型预测成交概率与真实成交的校准报告。

## M5 — AI 扩展

各组件独立触发。

| 组件 | 启动触发条件 | 交付内容 |
|---|---|---|
| `oq-infer` | 有训练好的模型要进入回路 | 进程内 ONNX 与编译树推理、预热与固定形状、Python/Rust 预测 parity 门（**G9**） |
| `oq-env` | L1 保真度达成（M4） | 控制反转的 gym 式环境 + 原生向量化批处理，seed 贯穿每个随机源（**G10**） |
| `oq-features` | 随 `oq-infer` 一同 | PIT 特征层，研究与实盘共用一条代码路径，线上/线下一致性度量 |
| `oq-lab` | 仅时间盒探索 | LLM 沙盒，配类型化只读工具 API 与审计日志。无验收目标，无兼容承诺 |

**关于 `oq-lab`。** LLM 驱动策略发现的公开证据很弱：对该领域文献的可复现性审计
几乎找不到能复现的结果，而且模型训练数据通常已经"见过"被评估的回测窗口。我们
保留这个实验沙盒，因为工具成本低、期权价值真实；我们把它标为实验性，因为假装
不是这样是不诚实的。评估只使用模型训练截止日之后的数据。

## 通往 1.0

1.0 是一项 **API 稳定承诺**，不是功能数量的门槛。它要求：

- M3 完成，且框架在维护者机器之外的地方跑实盘。
- 公开 crate API 与 Python 绑定面经过稳定性评审；已知设计错误在冻结**之前**改掉。
- 事件 schema 版本化，并有文档化的演进政策（只加字段，永不复用字段）。
- 连接器契约的文档化程度足以让第三方在不阅读适配器内部实现的情况下写出适配器。
- 文档覆盖快速上手、架构、保真度语义、保证金语义与运维。
- 自此严格执行语义化版本。

## 发布节奏

| 通道 | 节奏 | 内容 |
|---|---|---|
| `main` | 持续 | 永远绿；属性测试与 golden 守住每一次合并 |
| 预览 `0.x` | 按里程碑 | 每个里程碑验收门通过时打 tag |
| 补丁 | 按需 | 正确性修复；绝不静默改变引擎语义 |

任何对 L0 撮合语义、保证金计算或事件 schema 的改动，都必须在 changelog 中显式
说明，并附一份展示行为差异的 parity 报告。golden 基线只有在 PR 中记录了人工
确认后才能重新生成。

## 风险清单

| 风险 | 等级 | 缓解措施 |
|---|---|---|
| 实现过程中 L0 语义走样 | 高 | parity 工具先行；每一处差异都归因，不放行任何一条 |
| 保证金规则复现错误（分级表、全仓细节） | 高 | 规则双时间存储；与交易所强平计算器抽样核对；单调性属性测试 |
| 达速模式改造引入行为漂移 | 高 | 达速模式独立重新通过 parity 门 |
| PyO3 回调开销主导 Python tier | 中高 | 双模式设计隔离该风险；兼容模式本就不承诺速度 |
| 采集基建规模不足（流量、gap、成本） | 中高 | 专用采集机 + 本地存储 + 批量归档；先做 7 天试采实测流量、gap 率与成本再定 |
| L1 校准数据不足 | 中 | 采集从 M0 开始；数据足够之前只启用保守排队档 |
| 类型系统分裂成 Rust 与 Python 两种方言 | 中 | 单一类型系统铁律；绑定暴露同一套类型，绝不搞平行模型 |
| 范围膨胀 | 高 | 承诺范围止于 M2，之后一律触发制 |
| 专有内容泄漏进公开仓库 | 高 | 全新 git 历史；CI 秘密与模式扫描；专有内容只存私有 overlay；发布前人工审计 |
| bus factor = 1 | 中高 | 面向 agent 的代码库（每 crate `AGENTS.md`、分层验证锚）；行为以确定性测试固化；设计理由全部落纸，不留脑内 |
| 把"做完框架"当成目标本身 | 高 | 每个里程碑写明它解锁什么能力；每道门都问一次"到底什么被可度量地改善了" |

## 如何关注与参与

里程碑进度通过 GitHub issues 与 milestones 跟踪。当前价值最高的贡献依次为：

1. 带复现 seed 的精确 bug 报告——确定性让这类报告格外可操作。
2. 按连接器契约编写的交易所适配器。
3. 为 `oq-sim` 贡献描述通用失败模式的场景。
4. 文档与翻译。

见 [CONTRIBUTING.md](../CONTRIBUTING.md)。支持为 best-effort，1.0 前无 SLA。
