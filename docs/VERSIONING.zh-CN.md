# 版本规则

> [English](VERSIONING.md)

**"这是什么版本"只有一个答案。** 这份文档存在，是因为曾经有三个。

## 规则

工作区里每个 crate 的版本相同，在根 `Cargo.toml` 里声明一次，各 crate 用
`version.workspace = true` 继承。内部依赖也在 `[workspace.dependencies]` 里声明
一次——所以升版本是**一处修改**，不可能在 crate 之间漂移。

```
2.0.0-alpha.N   现在 —— API 会在不预告的情况下变动
2.0.0-beta.N    beta 里程碑起 —— API 已文档化，但仍会动
2.0.0           API 稳定；从此执行语义化版本
```

这些 crate 是**同一列发布火车**。它们是可分离的——单独使用其中一个是被支持且被
测试的性质（G0）——但它们一起开发、一起测试、一起发布，读者对比两个检出时不该
需要去调和十二个数字。

## 为什么是 2，而公开的东西从来没有过 1

OpenQuanter 1.x 是一个闭源交易平台，实盘运行了数年。它从未公开，也不会公开。
本项目是它的继任者，从零重写——**叫 2 只是对这件事的如实陈述**。

由此产生的结果是公开记录里有一个缺口：crates.io 和这个仓库都从 `2.0.0-alpha`
开始，**不存在可供查找的公开 1.x**。这一点写在这里、而不是留作谜题，因为一个
缺失的主版本号在读者眼里默认是个错误。

## 为什么用预发布标记而不是 0.x

两种约定都能表达"不稳定"。`0.x` 是 Rust 的惯常选择；这里选 `2.0.0-alpha.N`，
是因为另一条路会导致**两套编号同时存在**——一个自称"2.x"的项目，crate 版本写着
`0.0.1`，路线图指向"1.0"。读者无从判断哪个才是答案。

而且 cargo 的预发布语义正是我们想要的行为：`2.0.0-alpha.1 < 2.0.0`，且
`cargo add oq-core` **不会**自动选到预发布版本，除非显式要求。会不预告改 API 的
软件，本就应该要求使用者明确表态——这让它成为默认行为，而不是 README 里的一句警告。

## 每个阶段承诺什么

| 阶段 | 承诺 |
|---|---|
| `2.0.0-alpha.N` | 无。任何 API 都可能在任何一次发布中改变。变更记入[变更日志](../CHANGELOG.zh-CN.md)，**没有弃用缓冲期** |
| `2.0.0-beta.N` | API 已文档化、不太会动，但仍允许破坏性变更，且会被显式指出 |
| `2.0.0` | 公开 crate API 与 Python 绑定面稳定。破坏性变更需要升主版本 |

到达 `2.0.0` 是一项**承诺**，不是功能数量的门槛。它的条件见[路线图](ROADMAP.zh-CN.md)。

## 刻意独立编号的东西

不是所有东西都跟随 crate 版本，因为它们并不随之变化：

| 制品 | 版本位置 | 规范 |
|---|---|---|
| 采集文件格式 | manifest 里的 `format_version`，当前为 1 | [采集格式规范](CAPTURE-FORMAT.zh-CN.md) |
| Tick 文件格式 | 文件头里的 `version`，当前为 2 | [Tick 格式规范](TICK-FORMAT.zh-CN.md) |
| Journal 帧格式 | 帧头里的 `VERSION` | `oq-journal` |

**数据格式比写它的代码活得久。** 把格式版本绑到 crate 版本上，要么每次发布都要升
格式版本——那这个数字就没有意义了；要么让它落在后面——那它就是个谎。它们是两个
数字，因为回答的是两个问题：crate 版本说的是**你在对着什么 API 编译**，格式版本
说的是**磁盘上那个文件里装着什么**。

## 发布到哪里

| 产物 | 仓库 | 状态 |
|---|---|---|
| `openquanter`（Python） | [PyPI](https://pypi.org/project/openquanter/) | 已发布，`2.0.0a1` |
| `oq-*`（Rust） | crates.io | 名称已占位，未发布任何版本 |

Python 包先行、Rust crate 后发，是有意为之。一个绑定的暴露面是小的、被刻意挑
选过的——统计量和策略层——它的用户是在评估这东西值不值得花时间的人。而一个 crate
会暴露工作区里每一个 public 类型，而这些类型还在动。现在发布等于把人钉在一个即将
在他们脚下改变的版本上，而一个从 crates.io 撤下的版本，仍然是有人据以构建过的版本。

顺带说明：PyPI 的版本同样不可重传。`2.0.0a1` 是永久的，所以随它一起发出去的元
数据——描述、README、分类标签——是在上传**之前**检查的，而不是事后再改。

## 怎么改版本

改根 `Cargo.toml` 里的 `[workspace.package].version` 和 `[workspace.dependencies]`
中的版本。**没有别的地方。** 如果你发现自己在改 `crates/*/Cargo.toml` 里的版本，
说明有东西漂回去了，应该把它重新指向 workspace。
