# OpenQuanter — 需求规格说明

> 状态：**评审稿** · [English](REQUIREMENTS.md)
> 适用范围：OpenQuanter 2.x（Rust 核重写版本）
> 配套文档：[路线图](ROADMAP.zh-CN.md) · [实施方案](IMPLEMENTATION.zh-CN.md)

OpenQuanter 2.x 是在 Rust 确定性事件核之上对 OpenQuanter 的**从零重写**。它是
一套全新架构，而不是增量移植：早期 Python/Cython 版本只提供我们需要复现的语义
参考，其结构不被继承。本文档规定**框架必须做什么**，以及**怎样才算做到了**。
排期见[路线图](ROADMAP.zh-CN.md)，实现方式见[实施方案](IMPLEMENTATION.zh-CN.md)。

---

## 1. 定位

**一句话。** OpenQuanter 是一个确定性、AI-native 的量化交易框架：单一 Rust
事件核同时驱动回测与实盘，执行保真度与账户保真度可以独立选择，机器学习是一等
公民而不是外挂。

**生态位。** 这个赛道已经有强力选手——成熟消息总线架构的多资产 Rust/Python
引擎、带排队位置建模的加密高频回测器、面向中国期货市场的大型 Python 生态。
OpenQuanter 瞄准的是它们目前都没有同时覆盖的交集：

| 差异点 | 为什么重要 |
|---|---|
| **保证金与强平作为正交保真层** | 永远不会爆仓的回测，在尾部会系统性高估杠杆策略。任何保真档都可以叠加 `+margin` 运行。 |
| **加密永续优先** | 资金费、标记价格、分级维持保证金、强平订单流都是原生建模，而不是用股票账户模型近似。 |
| **AI 按证据强度分层** | 进程内推理是生产级能力；RL 环境只有在仿真保真度足够时才提供；LLM 研究明确标注为沙盒实验。 |
| **确定性即产品特性** | 重放、审计、崩溃恢复、随机化仿真测试是同一套机制，而不是四个子系统。 |
| **中英双语项目** | 文档与社区支持同时覆盖中英文。 |

**明确不宣称的事。** OpenQuanter 不提供 alpha。它提供的是让 alpha 研究诚实的
机械装置：保真度报告、过拟合统计、确定性复现，以及一个真的会把你的模拟账户
打爆的保证金模型。

## 2. 目标用户与使用场景

| 用户 | 主要场景 | 依赖的能力 |
|---|---|---|
| 策略研究员 | 参数扫描、假设验证、尾部风险评估 | Python tier、L0/L0+margin 回测、DSR/PBO 统计、分析导出 |
| 系统化（CTA 型）交易者 | 中频策略实盘运行 | Python tier、Rust 网关、风控闸门、journal 审计流 |
| 做市 / 高频研究者 | 排队感知的仿真、订单簿信号 | Rust tier、L1/L2 保真度、延迟模型 |
| ML 实践者 | 模型上线、RL 实验 | ONNX/编译树推理、向量化环境、PIT 特征层 |
| 运维 | 部署、监控、事故取证 | CLI、journal 审计流、对账、结构化指标 |
| 框架集成者 | 接入新交易所、嵌入内核 | 稳定的 crate 边界、连接器契约、一致性测试套件 |

**私有 overlay** 部署模式是一等公民场景：专有策略、参数与采集数据放在私有仓库，
单向依赖公开 crate。公开仓库永不包含专有内容，公开设计的任何部分都不假设私有
组件存在。

## 3. 功能需求

按领域分组。每条标注稳定性预期：**Core**（1.0 必须具备）、
**Extended**（已规划，受里程碑触发条件约束）、**Experimental**（时间盒探索，
不承诺兼容性）。

### 3.1 事件核 — `FR-CORE`

| ID | 需求 | 层级 |
|---|---|---|
| FR-CORE-1 | 内核形如 `apply(&mut State, Event) -> Outputs` 的纯状态机，内部禁止读时钟、用随机数、做 I/O、开线程。 | Core |
| FR-CORE-2 | 时间只以注入的 `TimeEvent` 进入内核。回测、沙盒、实盘只在事件生产者与时钟源上有差别。 | Core |
| FR-CORE-3 | 每个事件先定序、先追加写入 mmap journal，**然后**才进入内核。 | Core |
| FR-CORE-4 | 任何一次运行都可由 `(journal, seed, commit)` 逐位复现；重放 journal 必须产生完全相同的输出。 | Core |
| FR-CORE-5 | 状态快照由流内事件触发；恢复 = 快照 + journal 尾部重放，并容忍最后一条撕裂记录。 | Core |
| FR-CORE-6 | 内核按标的分片，片内单线程。跨片交互只经定序事件流，不共享可变状态。 | Core |
| FR-CORE-7 | journal 读者（监控、分析、IPC 消费者）是观察者，永远不能影响内核状态。 | Core |

### 3.2 撮合与保真度 — `FR-MATCH`

| ID | 需求 | 层级 |
|---|---|---|
| FR-MATCH-1 | 撮合按**保真度阶梯**组织（§6）；每次运行的输出都记录所选档位。 | Core |
| FR-MATCH-2 | L0 语义（tick 回放 + 可配置穿越规则）一经发布即冻结，作为迁移与回归的锚点。 | Core |
| FR-MATCH-3 | 每次回测输出**保真度报告**：参与率、maker/taker 占比、延迟假设、冲击扣减；开启保证金时还包括峰值保证金占用与最近强平距离。 | Core |
| FR-MATCH-4 | 实测参与率超过可配置阈值时标红：一旦模拟策略会推动市场，基于回放的回测就失效了。 | Core |
| FR-MATCH-5 | L1 增加排队位置建模、三段延迟（feed / entry / response）、taker 平方根冲击罚项。 | Extended |
| FR-MATCH-6 | L2 由增量深度重建订单簿并在其上撮合，配合周期性快照对账与 gap 检测。 | Extended |
| FR-MATCH-7 | 撮合逻辑写成纯函数并由属性测试覆盖：数量守恒、价格时间优先、无交叉盘、无负成交。 | Core |

### 3.3 保证金、资金费与强平 — `FR-MARGIN`

这是差异化子系统，且与保真度阶梯**正交**：任何档位都可开启保证金。

| ID | 需求 | 层级 |
|---|---|---|
| FR-MARGIN-1 | 按交易所、按合约建模分级维持保证金表，并**双时间（bitemporal）存储**——交易所规则会静默变更，历史回测必须使用当时生效的规则。 | Core |
| FR-MARGIN-2 | 每个相关 tick 重算保证金占用与强平价；交易所以标记价格计算的，就用标记价格而非最新成交价。 | Core |
| FR-MARGIN-3 | 触发强平时，强平单像普通订单一样进入撮合引擎，并遵循同一保真档位。 | Core |
| FR-MARGIN-4 | 按交易所时刻表结算资金费，并可注入资金费尖峰场景做压力测试。 | Core |
| FR-MARGIN-5 | 框架可产出**尾部偏差报告**：同一策略同一数据在开/关保证金两种模式下对比，量化无保证金仿真的乐观程度。 | Core |
| FR-MARGIN-6 | 全仓、逐仓，以及（交易所支持时）组合保证金模式可区分。 | Extended |
| FR-MARGIN-7 | 属性测试强制：保证金占用非负、强平价随仓位规模按预期方向单调变化、手续费与资金费应用过程中权益守恒。 | Core |

### 3.4 策略层 — `FR-STRAT`

| ID | 需求 | 层级 |
|---|---|---|
| FR-STRAT-1 | **Tier A**：以 Rust trait 实现的策略，在热路径上进程内运行。 | Core |
| FR-STRAT-2 | **Tier B**：经 PyO3 的 Python 策略，与 Tier A 共用一套类型系统——不存在平行对象模型，不存在 v1/v2 分裂。 | Core |
| FR-STRAT-3 | Tier B 提供两种模式：**兼容模式**（朴素逐事件回调，优先易于移植，不承诺吞吐）与**达速模式**（订阅粒度控制、批量回调、状态镜像）。 | Core |
| FR-STRAT-4 | 同一份策略源码在回测、沙盒、实盘中无改动运行；环境差异是配置，不是代码。 | Core |
| FR-STRAT-5 | 策略可表达下单、撤单、改单；框架保证每一条在发送前已落 journal。 | Core |
| FR-STRAT-6 | 常用指标与仓位管理组件以可复用构件形式提供，而不是策略必须继承的类层次。 | Core |

### 3.5 风控 — `FR-RISK`

| ID | 需求 | 层级 |
|---|---|---|
| FR-RISK-1 | **RiskGate** 位于策略输出与任何交易所之间，策略代码无法绕过——包括编译进同一二进制的 Tier A 策略。 | Core |
| FR-RISK-2 | 盘前检查覆盖：名义价值与仓位上限、下单频率、价格合理性带、自成交防护、标的白名单。 | Core |
| FR-RISK-3 | Kill switch 可停止全部订单发出并可选平仓，CLI 与运维信号均可触发。 | Core |
| FR-RISK-4 | 启动时及此后周期性地与交易所对账仓位、订单、余额。**未知状态即致命**：无法调和的差异必须停止交易，而不是猜测。 | Core |
| FR-RISK-5 | 风控限额是版本化且落 journal 的配置——改限额本身就是一条可审计事件。 | Core |

### 3.6 交易所接入 — `FR-VENUE`

| ID | 需求 | 层级 |
|---|---|---|
| FR-VENUE-1 | 交易所适配器实现文档化的连接器契约：行情、订单、用户流、对账是可分离的关注点。 | Core |
| FR-VENUE-2 | **一致性测试套件**用录制数据与合成异常检验每个适配器，涵盖回报丢失、重复、乱序。 | Core |
| FR-VENUE-3 | 对账在每个适配器中都是一等设计对象，而非事后补丁——启动时交易所是真相源。 | Core |
| FR-VENUE-4 | 订单 ID 从第一天起支持 broker / 返佣前缀方案，集成方无需改适配器即可归因流量。 | Core |
| FR-VENUE-5 | 凭证永不从提交的配置文件读取；适配器从环境变量或 OS keyring 获取，且只有网关进程持有。 | Core |
| FR-VENUE-6 | 1.0 时至少提供一个主流永续交易所的参考适配器，后续交易所遵循同一契约。 | Core |

### 3.7 数据平面 — `FR-DATA`

| ID | 需求 | 层级 |
|---|---|---|
| FR-DATA-1 | 每条行情记录携带**双时戳**：交易所时间与本地接收时间，均为纳秒精度。 | Core |
| FR-DATA-2 | 存储为列式（Arrow/Parquet）并有文档化 schema；时序数据库集成是可选项而非前提。 | Core |
| FR-DATA-3 | 随时间变化的参考数据（资金费时刻表、保证金分级、合约规格、上下架）双时间存储。 | Core |
| FR-DATA-4 | as-of join 默认使用**严格 `<`** 语义；框架不得静默允许同时戳记录泄漏进特征。 | Core |
| FR-DATA-5 | 采集工具原样录制交易所原始流——不合并、不降频——重连时打 gap 标记，并记录时钟偏移估计。 | Core |
| FR-DATA-6 | PIT 特征层用一份代码同时服务研究与实盘，并输出线上/线下一致性漂移度量。 | Extended |

### 3.8 研究工作流 — `FR-RESEARCH`

| ID | 需求 | 层级 |
|---|---|---|
| FR-RESEARCH-1 | 参数扫描是一等命令，支持并行执行与结构化结果输出。 | Core |
| FR-RESEARCH-2 | 扫描自动输出 **Deflated Sharpe Ratio** 与 **Probability of Backtest Overfitting**，并跨扫描跟踪试验次数。 | Core |
| FR-RESEARCH-3 | 超过过拟合阈值的结果被标记；严格模式下拒绝打包部署。 | Core |
| FR-RESEARCH-4 | 回测输出对分析友好：逐笔交易记录、权益曲线、保真度报告，均为开放格式。 | Core |
| FR-RESEARCH-5 | **Parity 工具**对两次运行做逐笔 diff 并给出差异归因——用于验证移植、重构与保真档位变更。 | Core |
| FR-RESEARCH-6 | parity 与 golden 基线由三元组标识：**(代码 commit、输入数据内容哈希、生效配置哈希)**。 | Core |
| FR-RESEARCH-7 | 三元组中任一元素与被测运行不符时，工具必须报 **`基线已失效——需 rebase`** 并指明是哪一元变了。只给出一个让人去猜原因的裸 mismatch 不是可接受的输出。只有三元全部一致时，差异才被报告为行为回归。 | Core |

### 3.9 AI 与 ML — `FR-AI`

按证据强度分层：可靠的直接交付，其余如实标注。

| ID | 需求 | 层级 |
|---|---|---|
| FR-AI-1 | 进程内推理：ONNX 运行时与编译后的梯度提升树可在热路径调用，延迟有界、单次调用零分配。 | Extended |
| FR-AI-2 | **预测 parity 门**校验 Rust 推理路径与 Python 训练路径在容差内一致，捕获树模型 float32 阈值漂移。 | Extended |
| FR-AI-3 | 控制反转的 gym 式环境 + 原生向量化批处理，seed 贯穿每一个随机源。 | Extended |
| FR-AI-4 | RL 环境以 L1 保真度为前置条件：在低保真环境训练等于教模型利用仿真器缺陷。 | Extended |
| FR-AI-5 | LLM 驱动的研究运行在沙盒中，配类型化只读工具 API 与完整审计日志。LLM 输出是*提案*，硬限制永远在引擎层。 | Experimental |

### 3.10 运维与工具 — `FR-OPS`

| ID | 需求 | 层级 |
|---|---|---|
| FR-OPS-1 | 单一 CLI 覆盖 `backtest`、`sweep`、`live`、`replay`、`parity`、`data` 子命令。 | Core |
| FR-OPS-2 | 推荐实盘拓扑为**每账户一进程**：一个进程拥有一个账户、其策略集与独立 journal，一个账户的故障不会污染另一个。跨进程聚合通过读 journal 实现。 | Core |
| FR-OPS-3 | 平滑重启通过快照、重连、对账保住持仓与在途订单。 | Core |
| FR-OPS-4 | 存在文档化的**带仓切换流程**，投入生产前先在测试网演练。 | Core |
| FR-OPS-5 | 延迟敏感路径以直方图（而非均值）方式输出指标，且测量边界定义清晰。 | Core |
| FR-OPS-6 | 时钟纪律有文档且可验证：主机运行 NTP/chrony，采集进程将时钟偏移估计随数据归档。 | Core |

## 4. 非功能需求

| ID | 需求 |
|---|---|
| NFR-1 **确定性** | 内核内禁止读时钟、随机数、I/O、线程。由评审、尽可能的 lint、以及 CI 中的重放测试共同强制。 |
| NFR-2 **延迟** | 实盘热路径，从 journal 写入到订单字节离开网关 socket：p99 ≤ 100 µs。JSON 解析与请求签名各自单列预算并单独报告。 |
| NFR-3 **吞吐** | 达速模式下，单策略多年 tick 回放回测至少比等价解释型/Cython 实现快 8×。 |
| NFR-4 **内存** | 热路径预热后零分配；缓冲区按分片预分配。 |
| NFR-5 **可移植性** | 主目标 Linux x86-64；macOS（Intel 与 Apple Silicon）支持开发。Python 绑定按 abi3 覆盖受支持的 CPython 版本。 |
| NFR-6 **安全性** | `unsafe` 默认告警，使用需在评审中给出理由。零拷贝布局使用经审计的 crate，而非手写 transmute。 |
| NFR-7 **定点纪律** | 热路径用 `i64` 定点；decimal 只出现在账本与报表边界。**浮点永不用于金额**。 |
| NFR-8 **Schema 演进** | 序列化事件字段**永不复用**。新语义用新字段；旧字段标记废弃，不重新赋义。 |
| NFR-9 **上手成本** | 新用户从干净机器到跑通示例回测 ≤ 30 分钟，使用随仓库分发的样例数据。 |
| NFR-10 **面向 agent 的代码库** | 每个 crate 配 <200 行 `AGENTS.md`，写明本地命令与不变量。验证分层：单测 → 属性 → golden → parity。golden 基线变更须人工显式确认。 |
| NFR-11 **抗 bus-factor** | 设计理由写进仓库，不留在某个人脑子里。行为知识以确定性测试固化，而非口口相传。 |
| NFR-12 **版本策略** | 1.0 前：次版本即可能破坏 API，变更记入 changelog。1.0 后：公开 crate API 与 Python 绑定面遵循语义化版本。 |

## 5. 可度量验收目标

每个目标都有定义好的验证方式。验证没有跑在 CI 里、或没有一条可复现的文档化
命令，就不算达成。

| # | 目标 | 目标值 | 验证方式 |
|---|---|---|---|
| **G1** | 内核确定性 | 重放任意 journal 输出完全一致；`(seed, commit)` 可复现任意仿真场景 | CI 中的重放测试套件 |
| **G2** | 语义 parity 工具 | 与参考实现逐笔一致（时刻/价格/数量/方向），P&L 相对误差 ≤ 1e-6 | `oq-parity` diff + 归因报告 |
| **G3** | 回测吞吐 | 达速模式下多年单策略跑批较解释型/Cython 基线 ≥ 8×；兼容模式仅要求不退化 | 同机同配置基准测试 |
| **G4** | 扫描吞吐与统计 | 参考机器上 100 组配置 ≤ 30 分钟，自动输出 DSR 与 PBO | 扫描基准 + 统计报告 |
| **G5** | 保证金保真 | 分级维持保证金、标记价强平路径、资金费尖峰场景复现交易所行为；产出尾部偏差报告 | 历史极端行情复算 + 与交易所计算器抽样核对 |
| **G6** | 实盘热路径延迟 | journal 写入 → socket 写出 p99 ≤ 100 µs | HDR 直方图埋点 |
| **G7** | 策略可移植性 | 策略在兼容模式下零改动运行；同一策略在达速模式下达到 G3 并重新通过 G2 | 两种模式各自基准 + parity |
| **G8** | 高频保真 | L1 排队 + 延迟 + 冲击；L2 订单簿重建；风格化事实测试集通过 | 保真度测试套件 + 校准报告 |
| **G9** | 推理 | 进程内 GBDT 单行推理 ≤ 10 µs；Python/Rust 预测 parity 门通过 | 推理基准 + parity 测试 |
| **G10** | RL 环境 | 向量化批量环境，seed 全贯穿，训练可复现 | 训练吞吐基准 + 复现测试 |
| **G11** | 采用就绪度 | 冷启动到首次回测 ≤ 30 分钟；公开 CI 全绿；1.0 后遵循语义化版本 | 外部用户冷启动实测 |

## 6. 保真度阶梯

保真度是两个独立维度：**执行真实度**（阶梯）与**账户真实度**（保证金叠加层）。
每次运行都声明这两项。

| 档位 | 撮合语义 | 数据要求 | 典型用途 |
|---|---|---|---|
| **L0** | tick 回放 + 可配置穿越规则；冻结为回归锚点 | 成交/tick 序列 | 快速扫描、CTA 研究、迁移验证 |
| **L0 + margin** | L0 叠加完整保证金层 | L0 数据 + 标记价 + 保证金规则表 | **杠杆策略的诚实尾部风险** |
| **L1** | 排队位置模型、三段延迟、平方根冲击罚项 | tick + BBO + 校准样本 | 上线前验证、maker 策略初筛 |
| **L2** | 由增量深度重建订单簿并在其上撮合 | 完整增量深度 + 周期快照 | 做市、高频研究 |
| **L3 / 交互式** | 逐单 FIFO，或反应式仿真 | MBO 数据 / 校准模型 | 远期研究方向 |

**阶梯规则。**

1. 更高档不自动等于"更好"——它更贵，而且需要你可能并不拥有的数据。框架报告
   一次运行**实际**做了什么假设，而不是暗示它支撑不起的真实度。
2. 保证金叠加层与每一档都可组合。
3. 生成式订单簿仿真器是研究工具，永远不作为策略 P&L 的判定源。
4. 参与率超阈值时，无论哪一档，回放类结果都标记为超出适用域。

## 7. 非目标

- **不做**：kernel bypass、FPGA、自研网卡驱动。延迟目标在用户态可达，复杂度
  在此不划算。
- **不做**：热路径上的外置消息总线（Redis 之类）。journal 就是总线。
- **不做**：由通用 schema 生成的统一交易所抽象层。适配器按交易所逐个编写，
  因为交易所语义确实不同。
- **不做**：内核里带工作窃取的 async 运行时。async 只留在网关边缘。
- **不做**：为 Rust 与 Python 维护两套对象模型。
- **不做**：把生成式仿真器当作 P&L 判定源。
- **不做**：托管用户策略并保管用户 API key。托管密钥是本项目不愿承担的负债类别。
- **不承诺**：1.0 前的 API 稳定性，或任何支持 SLA。社区支持为 best-effort。
- **不交付**：带生产参数的交易策略、专有数据集，或任何近似投资建议的内容。

## 8. 仓库边界政策

公开仓库包含框架、教学示例、样例数据与公开 CI。它**永不**包含生产策略、实盘
参数、凭证、专有采集数据、部署拓扑细节或事故记录。在生产中使用本框架的用户，
应当把这类内容放进单向依赖公开 crate 的私有 overlay 仓库。

这是一条硬规则，并对公开设计产生三条推论：

1. 公开质量门基于**样例数据 golden + 属性测试**，永不要求访问私有数据集。
2. 公开贡献的仿真场景描述**通用失败模式**（乱序回报、部分成交竞态、行情断流），
   而非任何部署的运营细节。
3. 每个公开接口都必须在没有任何私有组件的情况下可用、可测。

## 9. 术语表

| 术语 | 含义 |
|---|---|
| **Journal** | 追加式 mmap 事件日志；同时是审计流、重放源、恢复机制与进程间传输。 |
| **Sequencer** | 为事件分配全序并在内核看到之前写入 journal 的组件。 |
| **保真档位** | 所选的执行真实度级别（L0–L3）。 |
| **保证金叠加层** | 正交的账户真实度层，增加维持保证金、强平与资金费。 |
| **Parity** | 两次运行之间的逐笔语义一致性，并对差异做归因。 |
| **兼容模式** | Python tier 中面向快速移植优化的模式，不承诺吞吐。 |
| **达速模式** | Python tier 中带批量回调与订阅控制的模式，满足吞吐目标。 |
| **DSR / PBO** | Deflated Sharpe Ratio / 回测过拟合概率——扫描级过拟合统计。 |
| **参与率** | 模拟策略会吃掉的市场成交量占比；回放式回测的有效性边界。 |
| **VOPR 式仿真** | 随机化、seed 可复现的全系统故障仿真。 |
