# OpenQuanter

**Rust 写的量化交易组件。整套拿走，或者只拿其中一个 crate。**

> ### 回测与实盘之间的每一分差额，都说得清。
>
> **无法解释的收益，不算收益。**
>
> 差额拆到滑点、排队未成交、资金费、延迟、手续费档位，拆不动的那部分记为
> **未解释残差**——那个数字才是这个项目的成绩单。
>
> 这是目标，不是现状。差多远，见[当前状态](#当前状态)。

**给谁用。** 钱在里面、且要向人交代的杠杆交易者；正在重写或迁移引擎、需要证明
行为没变的团队；需要把结果拿给第三方看的人。**不面向**想要大而全指标库、几十家
券商接入或云托管的用户——那几样和可审计性直接冲突。理由和取舍见
[为什么有 OpenQuanter](docs/WHY.zh-CN.md)。

## OpenQuanter 是什么？

大多数交易框架是**平台**：你在它的世界里、按它的规矩、连同它的依赖树一起写代码。
OpenQuanter 是一组**你自己组装**的构件。

**整个引擎没有任何第三方依赖**——领域类型、journal、事件核、撮合、保证金、回测
宿主、数据平面、parity、统计，全是纯 std Rust。凡是带依赖树的 crate，都是必须和
交易所通信的那一类：采集、归档到 tick 的桥、账户读取器。**这条边界本身就是重点**，
而且由 CI 检查而不是口头声明：[`scripts/check-composability.sh`](scripts/check-composability.sh)
会在引擎 crate 沾上依赖、或交易所 crate 超出既定预算时让构建失败。（示例 crate
另外会拉 `criterion` 来跑基准；那是"文档"的 dev-dependency，不是任何人会依赖的
东西。）

所以你可以只用保证金模型而不要引擎，只用过拟合统计而不要回测器，只用采集工具而
完全不碰引擎。也可以整套用——同一个内核同时驱动回测与实盘，二者只差事件生产者。

**适用哪些市场。** 引擎不绑定资产类别：它消费的是带时间戳的行情事件和订单，而
股票、期货、外汇、加密货币都产生这些东西。各市场之间的差异被放在适配器后面——
如何订阅一个交易所、它的报文长什么样、**一个交易日是什么**、账户按哪套规则计保证金。

**先做加密永续，是因为它的对接最容易**：行情公开、无需资格审批，账户接入只要一个
API key 而不是一纸合同。这是关于上手成本的理由，**不是关于适用范围的**。下文凡是
写 *venue（交易所）* 的地方，指的就是你把它指向的那个市场；凡是写 *资金费率* 或
*标记价格* 的地方才是永续合约特有的，并会明确标注。

这些构件优先要做对的事，按顺序：

1. **一个不美化你的回测。** 分级保证金与强平是被建模的，不是被跳过的——见
   [实例](docs/QUICKSTART.zh-CN.md#3-跑那个解释了整个项目的示例)：无保证金的一臂
   声称赚了 20908 USDT，而真实账户只剩 61.53。
2. **不以保真度为代价的速度。** 整数定点、热路径无 async、预热后零分配。多数快的
   回测器是因为**省略了东西**才快；这里的重点是**不必二选一**——而且"不省略"的
   代价是一个数字，不是一句主张：

   ```
   cargo run --release -p oq-examples --example throughput

   throughput   35.38 M ticks/s      # 撮合 + 保证金 + 记账 + 策略
   ```

   关掉强平建模，同一个循环约 72 M ticks/s——也就是说**保证金保真的代价是大约一半
   的吞吐**。这正是本项目主张值得做的那笔交易；数字放在这里，是为了让你自己判断，
   而不是选择相信。测于 M4 Mac、seed 固定的行情、全内存——**不含 tick 文件的读取与
   解析**。用上面的命令复现；`cargo bench -p oq-examples` 给出完整分解。
3. **可复现、可审计的运行。** 定序落盘的事件流，使崩溃恢复、事故取证、研究复现
   三件事共用同一套机制。

### 它从哪来

OpenQuanter 1.x 是一个**闭源的交易平台，已经实盘运行数年**。它会一直闭源：里面
是策略、参数和运营历史，那些不是我们可以公开的东西。

这个项目之所以存在，是因为 1.x 撞到了天花板，而卡住的地方是**超大规模数据上的
回测吞吐**。这听起来像是个效率抱怨，但它不是。当一次参数搜索要跑几天而不是一个
下午，代价并不是等待本身——代价是**那些你悄悄不再尝试的研究**，是那些因为"验证它
不值得占用这么多日历时间"而从未被检验的假设。慢的研究不只是更慢，它会变成**另一种、
更小的研究**。

等到该做的 profiling 做完、显而易见的优化都上了之后，剩下的部分是结构性的。继续
调那套代码已经推不动了，因为限制来自架构而不是代码。所以 2.x 是**在 Rust 核之上
从零重写**，而不是增量移植。

有两件事值得直说。这里的每一处设计都是**跑真实系统、撞到真实的墙**之后长出来的
——保证金那部分之所以存在，是因为一个不会强平的回测已经悄悄美化了好几年的结果，
而不是因为它看起来像个好功能。以及：**最初的需求是一个特定用户的特定需要**，这也
正是本 README 以"这些构件是什么"开头、而不是以"那次迁移"开头的原因。

那堵墙的六个具体形态——沉默的失败、无法归因的差额、双实现的分歧、慢到缩小研究、
过期而不自知的结论、没有价格标签的过拟合——写在
[为什么有 OpenQuanter](docs/WHY.zh-CN.md)。

### 设计支柱

以下描述的是项目**正在建设的目标架构**。今天实际有什么见下方[当前状态](#当前状态)——
如果你在判断现在能不能用，请先看那一节。

- **可组合，不是单体** —— 每个 crate 都能独立构建、独立使用，且引擎不带任何
  第三方依赖。嵌入其中一块**不等于接受一个平台**，也不会扩大你的供应链暴露面。
- **确定性事件核** —— 由定序、落 journal 的事件流驱动的纯状态机（LMAX/Aeron
  谱系）。这是**机制，不是目的**：它让崩溃恢复、审计、研究复现、fuzz 测试成为
  同一套机器，而不是四个子系统。
- **带保证金的回测** —— 分级维持保证金、强平价路径、资金费尖峰场景都是一等
  公民。多数开源回测器永远不会爆仓，真实交易所会。
- **保真度阶梯** —— L0 tick 回放用于快速参数扫描 → 排队位置与延迟建模 →
  L2 订单簿重建。每次回测都会输出保真度报告（参与率、延迟假设、保证金峰值）。
- **双层策略** —— 延迟敏感策略用 Rust trait；研究迭代用 Python（PyO3）。
  单一类型系统，不维护两套运行时。
- **AI 一等公民** —— 进程内 ONNX / 编译树推理、向量化 gym 式训练环境、
  面向 LLM 研究的沙盒接口。
- **内建过拟合统计** —— 参数扫描默认输出 Deflated Sharpe Ratio 与
  Probability of Backtest Overfitting。
- **差额归因** —— 把实盘与回测的差额拆成滑点、排队位置、资金费、延迟、手续费
  档位，拆不动的部分报告为**未解释残差**。这是页首那句北极星的落地形态，也是
  这七条里**离得最远**的一条：它要求实盘进程记录决策 journal，而今天还没有。

## 当前状态

Pre-alpha，并且把话说清楚。**今天已建成并有测试覆盖的**：

- **确定性内核** —— 定序 journal、逐位精确的重放（有测试断言，含一条强平路径）、
  撕裂尾恢复、"先落盘再 apply"由故障注入测试强制。
- **L0 撮合** —— tick 回放，含跳空成交、价格改善、价格时间优先。已冻结为回归锚点。
- **保证金与成本** —— 分级维持保证金、强平价由推导得出而非照抄、资金费与尖峰注入、
  规则表双时间存储，以及 maker/taker 手续费（maker 费率可为负——返佣是存在的）。
- **回测宿主** —— 含保证金偏差报告：同一策略跑两遍，量化无保证金那一臂虚报了多少。
- **数据平面** —— 双时戳、无泄漏的 as-of join、双时间参考数据。
- **采集** —— 原样落盘的交易所记录 + 本地时戳、按 UTC 日或按小时密封、带内容哈希
  的 manifest。已对真实交易所验证。交易所是一个适配器：订阅哪些流、订阅如何被确认、
  交易所时戳在哪、每个品种的报价精度、以及**一个交易日是什么**——因为前一晚开盘的
  时段是一个交易日、两个 UTC 日。已实现两个交易所，而且刻意选了差异最大的一对：
  一个把订阅放在 URL 里、只能靠第一条数据确认，另一个发 JSON 帧并显式回执。
- **证明采集可用** —— 磁盘上的字节只能证明消息到过，只有重放才能证明它们**可用**。
  `oq-book-check` 重建订单簿，报告采集端未声明的断裂。`oq-trade-check` 追踪交易所
  自己的成交 id——**这是哈希校验给不了的**：id 连续就意味着一条没漏，而一个静默丢掉
  三分之一成交的采集，能通过管线里的每一道完整性检查。`oq-merge` 和 `oq-resequence`
  用于调和两个写入者或两次运行产生的归档。
- **采集到回测** —— `oq-ingest` 把采集到的深度和成交折叠成引擎重放的 tick 格式。
  转换是有意有损的：一个窗口的 L2 只留下最优买卖价，原始归档才是记录本身。已用真实
  的一天验证——978,118 条深度更新和 127,276 笔成交转成 26,237 个一秒 tick，无一条
  无法解析。
- **统计** —— Deflated Sharpe Ratio、回测过拟合概率、试验登记。
- **Parity** —— 逐笔 diff 与差异归因，基线由代码、数据、配置三者共同标识。

- **下单通路** —— 一套与交易所无关的执行契约,后面接着一个交易所。下单返回的是
  三种结局而不是两种:接受、拒绝,以及**未知**——因为超时不代表失败,只代表没人
  知道,而把它折进错误正是产生重复仓位的原因。每张单都带一个发送前就选定的 id,
  那是请求的回答没回来时唯一还在手上的把手。成交从另一条 socket 回来,断连被
  报成缺口而不是被抹平;而一条开着却已不再投递的 socket,靠连续三次与交易所自己
  的持仓视图不一致被抓出来。
- **盘前闸门** —— 单笔数量、成交后仓位、名义额、一条**价格带**(它拦得住名义额
  上限会直接放行的那种「少写一位数字」)、挂单数上限、频率上限,以及一个
  **kill switch**——按下去就一直是按下的,直到有人手动清除。检查通过返回的不是
  布尔值,而是一张**装着它所批准的那张单**的许可证,所以不可能检查了一张、发出去
  另一张。没人设过的限额拒绝一切。

**已设计但尚未建成**:保真度 L1 与 L2 档(目前只有 L0)、Python 策略层、
参数扫描器,以及上面「AI 一等公民」下的全部内容。设计支柱那一节讲的是方向,
这一节讲的是现状。

**关于实盘,单独说清楚**,因为上面那两条很容易被夸大。**整条循环已经对着真实
交易所的 testnet 跑通**:`oq-trade` 从该部署读取合约的精度、价格网格与最小名义额,
拒绝在一个自己不知道的仓位旁边启动,连上行情与账户流,聚合出 tick 交给策略,
把闸门批准的那张单发出去,**在账户流上看到同一张单**,撤掉它,**并在流上确认撤单
成功**——523 个 tick、一张单下出又撤回、零重复成交。

那几次运行是上面全部声称的证据,而且**每一次都抓出了单元测试到不了的东西**:一个
小数位完全合法、却不是 tick 整数倍的价格;一个被喂了写死零仓位的风控闸门,它的仓位
上限永远不可能触发;一个永远返回交易所所列第一个合约的查询,对一个品种是对的、
对其余六百个静默地错;一个被当成断连的读超时,在一个什么都没发生的市场上两分钟里
造成 14 次重连;以及一张低于交易所最小名义额的单——**知道精度和网格,不等于知道下限**。

**没有发生的是:一个有 edge 的策略、无人看管地、带着真钱在跑。** 随附的两个策略
刻意都不是策略:一个从不交易、只用来证明循环,另一个在远离市价处挂一张单再撤掉。

**组装已经有了**:`oq-live` 把行情、策略、风控闸门和下单通路接成一个进程。

**归因链已经接通第一段。** 实盘进程现在依赖 `oq-journal`,并在 `record.rs` 里
真的写——**可回放的原料有了**。

**第二段还没接。** `oq-live` 仍不依赖 `oq-core`,也不依赖 `oq-margin`:它和回测
共享的是策略代码与撮合类型(`oq-strategy` → `oq-engine`),**不共享内核、账本与
保证金模型**。所以现在的状态是有记录、却没有可以把记录回放进去的内核,也就仍然
无法逐笔比对出差额从何而来。

所以"每一分差额都说得清"目前**一分也说不清**——但缺口从两段变成了一段。
`oq-core` 有 `sequencer::replay()` 且有测试;**要接的是它和实盘之间那一根线。**

有一处名字容易撞车，说明一下：`oq-l2feed` 里的订单簿重建是**校验归档**的工具，
不是保真度的 L2 档。它重建订单簿是为了证明采到的数据可用；**对着重建出来的
订单簿撮合**属于 M4，尚不存在。

从[快速上手](docs/QUICKSTART.zh-CN.md)开始——三个示例、无需下载数据、几分钟内
就能跑起一次回测。各里程碑解锁什么能力、由什么触发，见[路线图](docs/ROADMAP.zh-CN.md)；
`2.0.0-alpha` 承诺了什么，见[版本规则](docs/VERSIONING.zh-CN.md)。
